# api — NestJS main API

The only back end the website talks to: admin login (JWT + bcrypt), courses, subjects, PDF upload/serving,
and it forwards searches to the Python service. The URLs it must offer are in [../docs/api-contract.md](../docs/api-contract.md).

## Folders

| Path                        | What                                                              |
|-----------------------------|-------------------------------------------------------------------|
| `prisma/schema.prisma`      | The 6 database tables. **Only place where the tables are defined.** |
| `prisma/migrations/`        | SQL history of the schema (created by Prisma)                     |
| `prisma.config.ts`          | Prisma 7 settings (where the schema is, database URL)             |
| `src/main.ts`               | Starts the server on port 3000                                    |
| `src/app.module.ts`         | Main module: add your new modules in `imports`                    |
| `src/app.service.ts`        | `GET /` hello: checks the database and the Python service         |
| `src/prisma/`               | `PrismaService`: inject it in any service to use the database     |
| `src/generated/prisma/`     | Generated by `npx prisma generate`, not in git                    |

## Next steps: create your modules

Each feature = one module with a controller (the URLs), a service (the logic) and DTOs (the data shapes):
```bash
npx nest g resource subjects
```
```bash
npx nest g resource courses
```
```bash
npx nest g resource auth
```
```bash
npx nest g resource search
```
Choose "REST API" and "yes" for CRUD entry points. Then use `PrismaService` in the service, e.g.
`this.prisma.subject.findMany()`.

## Prisma 7 notes

We use **Prisma 7**. Many tutorials online are for Prisma 5/6 and look a bit different. Follow the official
[NestJS + Prisma docs](https://docs.nestjs.com/recipes/prisma) and ignore tutorials that use `prisma-client-js`
or `import { PrismaClient } from '@prisma/client'`. We import from `../generated/prisma/client` and use the `PrismaPg` adapter.

The `embedding` column (pgvector) is `Unsupported` in Prisma: NestJS never touches it, the Python service does.

Change the tables:
1. Edit `prisma/schema.prisma`.
2. `npx prisma migrate dev --name what-you-changed` (with the database running).
3. Commit the new folder in `prisma/migrations/`.

## Run

With Docker (from the repo root): `docker compose up --build`. Migrations are applied automatically on start.

```bash
docker compose exec api npm test
```
```bash
docker compose exec api npx prisma studio
```

Without Docker (from `api/`, with `db` running and `localhost` instead of `db` in `.env`):
```bash
npm install
```
```bash
npx prisma migrate deploy
```
```bash
npm run start:dev
```
